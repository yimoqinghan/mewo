# 言喵微信云第一阶段接入说明

## 实施范围

本阶段标记为 P0，目标是把“猫咪档案 → 照片上传 → 生成任务 → 作品记录”从本地 Storage 迁移到微信·云开发，同时保留本地回退，便于继续在未配置环境时预览首页。

当前接入内容：

- 云数据库：`cats`、`assets`、`generation_tasks`、`works`
- 云存储：用户照片和后续生成图片，数据库只保存 `fileId`
- 云函数：`meow-api`
- 小程序端：`wx.cloud.init`、`wx.cloud.uploadFile`、`wx.cloud.callFunction`
- 真实 AI：暂未接入，当前云函数会生成一条明确标记为占位的成功记录

当前开发环境：`yanmiao-dev-d0grqyxj0cc290a96`（上海，个人版，PostgreSQL）。已在 PostgreSQL 环境中开通 Document/pgdoc 插件，因此现有小程序文档型 API 可以继续使用。

## 开通和配置

1. 在微信开发者工具中打开本项目。
2. 点击工具栏的“云开发”，创建开发环境。
3. 在云开发控制台复制环境 ID。
4. 修改 `miniprogram/config/env.js` 中的 `CLOUD_ENV_ID`：

```js
const CLOUD_ENV_ID = '你的云环境ID';
```

5. 在 Document 插件中创建 `cats`、`assets`、`generation_tasks`、`works` 四个集合，并把前端直读权限设为“无权限/仅管理端可读写”；业务读写统一经过云函数。
6. 在开发者工具中右键 `cloudfunctions/meow-api`，选择“上传并部署：云端安装依赖”。
7. 编译小程序，进入猫咪档案页新增一只猫，再进入创作页上传照片测试。

环境 ID 为空时，页面会继续使用本地 Storage 和本地模拟生成，不影响当前视觉开发。

## 数据集合

| 集合 | 用途 | 关键字段 |
| --- | --- | --- |
| `cats` | 猫咪档案 | `ownerOpenId`、`clientId`、`name`、`avatarFileId` |
| `assets` | 上传素材登记 | `ownerOpenId`、`fileId`、`purpose`、`status` |
| `generation_tasks` | 生成任务状态 | `ownerOpenId`、`catId`、`status`、`workId` |
| `works` | 作品记录 | `ownerOpenId`、`catId`、`imageFileId`、`saved` |

云函数使用微信上下文中的 `OPENID` 作为所有权依据，不信任客户端传入的用户 ID。图片默认按私密素材处理，展示时再换取临时链接。

## 后续接入真实 AI

把真实 AI 服务放到云函数或异步任务 worker 中，客户端只提交任务并查询状态：

```text
小程序上传照片
→ meow-api 登记素材
→ 创建 generation_tasks: queued
→ 云函数/任务服务调用 AI
→ 写入 works 和结果 fileId
→ 小程序轮询 succeeded / failed
```

AI 密钥只配置在云函数环境变量或云端密钥管理中，禁止写进 `miniprogram/`、`project.config.json` 或提交到仓库。

## 验收指标

- 未配置云环境时首页和本地预览不白屏。
- 配置云环境后照片能上传并返回 `fileId`。
- 猫咪档案、任务和作品能按微信用户隔离。
- 生成失败有明确错误提示，后续可以补充重试。
- 小程序包中不出现 AI 服务密钥、`AppSecret` 或永久公开图片地址。
