# 言喵微信小程序开发文档 V1.0

本文是言喵微信小程序的开发基线。后续新增页面、接口和功能，应先对照本文与 `AGENTS.md`，再进入实现。

## 1. 项目目标

言喵不是宠物信息流或复杂日记工具，而是一个让用户把自家猫快速变成 AI 作品的人猫关系创作产品。

首版必须优先验证：

- 用户是否愿意录入一只或多只猫咪身份；
- 用户是否能快速选择正确的猫咪进行创作；
- 用户是否愿意通过一张照片生成作品；
- 生成结果是否被认为“像我家猫”；
- 用户是否愿意保存或分享结果。

## 2. 技术基线

### 2.0 视觉资源现状

设计规范中提到的 `assets/approved-home-reference.png` 当前不在项目目录内。初始化页面暂以 `产品品牌logo背景/言喵AI猫咪生活首页.png` 和 `产品品牌logo背景/言喵猫咪贴纸标志.png` 作为视觉参考，后续补齐正式批准稿后，再进行一次视觉回归。

### 2.0.1 静态资源存储规则

- 所有运行时静态资源（图片、WebP、GIF、SVG、GLB、字体、音频、JSON 等）统一以 `server/public/assets/` 为版本化源文件目录。
- 部署时由 `deploy/deploy-server.sh` 自动执行 `npm run sync:assets`，同步到腾讯云 COS 的 `static/` 前缀；新增资源未完成同步和 CDN 验证前，不算上线。
- 小程序运行时通过 `https://static.missmeow.net/static/...` 或后端 `/assets/*` 路由访问，不直接引用 `miniprogram/` 内的资源副本，也不直接使用 COS 原始域名。
- 用户原照片和生成作品属于用户媒体，统一放在 COS 的 `u/` 前缀，不得混入公开静态资源目录 `static/`。

### 2.1 当前实现

| 项目 | 当前约定 |
| --- | --- |
| 客户端 | 原生微信小程序 |
| 语言 | JavaScript |
| 视图 | WXML |
| 样式 | WXSS |
| 本地数据 | `wx.setStorageSync` / `wx.getStorageSync` |
| AI 服务 | `miniprogram/services/generator.js` 占位 |
| 项目根目录 | 当前仓库根目录 |
| 小程序代码目录 | `miniprogram/` |

当前不引入第三方框架和构建依赖，先保证微信开发者工具可以直接打开和运行。后续如果需要 TypeScript、Taro 或云开发，应单独评估迁移成本，不在功能开发中途随意切换。

## 3. 产品功能优先级

### P0：首版必须完成

#### 多猫身份与档案管理

- 一个用户支持多只猫咪。
- 每只猫有独立的名称、照片、外貌、性格和偏好。
- 首页显示当前猫咪，支持快速切换。
- 拍照创作默认使用当前猫咪身份。
- 生成作品必须绑定 `catId`，多猫作品绑定 `catIds`。
- 支持创建、编辑、归档和后续删除。

#### 猫咪拍照生成异形/创意作品

这是产品第一优先级主功能，所有内容模板都归属于这条主链路：

1. 今日喵事
2. 猫咪新闻
3. 猫咪独白
4. 两脚兽观察日记
5. 猫咪语音吐槽
6. 情绪卡片
7. 猫咪语录
8. 猫咪身份证
9. 成长纪念卡
10. 杂志封面
11. 电影海报
12. 猫咪通缉令
13. 猫咪四格漫画
14. 人猫聊天截图
15. 人猫小剧场
16. 人猫双图连续漫画
17. 异形/创意猫咪图片

首版可以先实现少量模板，但产品架构必须以“模板可扩展”为前提，不能为单一模板写死数据结构。

### P0.5：高优先级基础能力

#### 猫咪人格与前世今生

- 建档后生成多种前世人物故事。
- 用户选择或微调性格。
- 形成角色设定书。
- 后续内容、数字猫和语音复用同一人格。
- 明确这是拟人化创作，不是事实判断或真实猫语翻译。

#### 喵喵相机基础美化闭环（P0.5）

- 用户从首页「喵喵相机」或创作页「重新拍摄」进入猫咪专属相机预览页。
- 首版提供原生相机预览、前后摄像头切换、闪光灯，以及「自然、补光、清晰、色彩」四项喵咪美化设置和轻滤镜。
- 内置「奶油喵、阳光喵、电影喵、糖果喵」模板；首次点击下载模板配置，下载后立即应用并缓存到当前用户。
- 拍摄或相册选图后，使用本地 Canvas 做轻量补光/色彩处理；处理失败保留原图，不阻塞生成。
- 美化工具图标使用图片模型生成的透明贴纸风资源，运行时使用压缩 WebP，并保留文字占位以应对慢网或加载失败。
- 确认照片后通过本地草稿回填创作页，继续沿用现有「参考图 → 生成作品」链路。
- 依赖：微信原生 `camera`、Canvas、`utils/adapter.js` 相机/画布封装；不依赖外部 License。
- 验收指标：从拍摄预览到生成页不超过 3 个主动步骤；照片默认私密；相机或美化失败时可重试或使用原图。
- 后续增强：接入具备 License 的美颜 SDK 后，再增加人像美妆、实时贴纸和高级面部特效；猫咪场景默认不启用瘦脸/大眼等人像变形。

### P1：基础陪伴能力

#### 数字猫基础形象

先做头像、角色卡和首页状态，不做复杂养成。

#### 语音陪伴基础版

先做预设音色、按住说话、文字回复和语音播放。实时低延迟、可打断对话和复杂情绪表达后置。

### P2：复杂扩展能力

#### AI 宠物短视频

需要考虑生成时长、成本、角色一致性、内容标识和审核。

#### 云上小家

先评估静态风格化房间，再考虑数字猫动作、物品和互动。完整空间养成属于后续版本。

#### “懂它”知识窗口

保留为辅助入口，不作为底部主导航。内容必须有健康安全边界，不能替代兽医诊断。

#### 猫咪时装秀

作为拍照创作中的扩展模板，不作为首版主入口，不优先建设投票榜单和公开秀场。

### P3：最低优先级

- 故事与共同记忆：完整日记、作品时间线、连载、年度回忆册。
- 轻社交：邮局、串门、照片墙和投票。
- 文创与实体化：挂件、漫画册、日历、摆件和语音 NFC 物件。

P0 可以保留“最近生成记录”，但它不等于完整的共同记忆系统。

## 4. 核心数据模型

### 4.1 猫咪档案

```js
{
  id: 'cat-xxx',
  name: '布丁',
  avatar: '/assets/brand-cat.png',
  age: '2 岁',
  traits: '黑猫 · 好奇',
  personality: '嘴硬心软',
  createdAt: 0,
  updatedAt: 0
}
```

### 4.2 作品

```js
{
  id: 'work-xxx',
  catId: 'cat-xxx',
  catIds: ['cat-xxx'],
  templateKey: 'comic',
  templateName: '猫咪四格漫画',
  inputAssets: [],
  outputAssets: [],
  text: '生成文案或剧本',
  visibility: 'private',
  status: 'succeeded',
  createdAt: 0
}
```

真实 AI 接入后，必须补充任务状态、失败原因、耗时、消耗额度和审核状态。

## 5. 页面和交互规范

- 首页只突出一个主任务：猫咪拍照生成。
- 用户常用路径尽量控制在三步以内。
- 当前猫咪必须在首页和创作页清晰可见。
- 所有生成页必须有加载中、成功、失败和重试状态。
- 私密素材默认不公开，不默认进入公共信息流。
- 真实照片、声音、家庭视频在上传前必须有用途说明和授权提示。
- 主按钮一屏最多 1–2 个，避免把所有能力平铺在首页。
- 颜色、间距、圆角、动效遵循 `设计skill/design-tokens.json`。
- 当前品牌名称统一使用“言喵”；英文标和品牌资产如需调整，必须先更新设计规范再改页面。

## 6. AI 与后端接入规则

当前 `services/generator.js` 只是模拟服务。接入真实服务时，建议拆分为：

```text
小程序
→ 业务 API
→ 生成任务队列
→ AI 图片/视频/语音服务
→ 内容安全审核
→ 对象存储与 CDN
→ 小程序查询任务结果
```

客户端不能直接持有模型密钥。图片、视频、声音和家庭空间素材应使用短期授权地址或服务端代理，不能把永久公开 URL 当作默认方案。

## 7. 隐私、内容安全与合规

- 用户照片、声音、家庭空间和猫咪资料默认私密。
- 二级页面顶部统一采用单一导航方案：页面使用自定义顶部栏时必须设置 `navigationStyle: "custom"`，由页面自己承载返回、标题和操作区；使用微信默认导航栏时，页面内容不得再重复放置页面标题栏。
- 分享必须由用户主动触发，并显示分享范围。
- AI 生成内容应在需要时标注 AI 生成。
- 猫咪翻译只能提供动作与声音的趣味推测，不能宣称真实翻译猫语或替代兽医诊断；视频和声音默认私密。
- 猫咪翻译同时支持猫叫分析与人话转喵语播放；人话转喵语只能作为趣味互动，不得宣称猫咪一定能理解。
- 不宣称可以真实翻译猫语、判断猫咪疾病或证明前世轮回。
- 健康知识只能提供观察提示，出现异常应建议咨询专业人士。
- 删除猫咪档案前说明是否影响相关作品；优先采用归档而非立即物理删除。
- 生产环境必须增加内容审核、投诉、违规处理和日志留存方案。

## 8. 当前阶段的已知限制

- 未登录游客模式使用本地 Storage 预览，不支持跨设备同步；登录后猫咪档案、聊天记录、直传媒体与 AI 作品走自建 HTTPS API + COS 私有桶。
- 猫咪翻译（`/v1/cat-translations`）与人话转喵语（`/v1/cat-speech`）目前仍为预览版 mock 分析器，尚未接入真实多模态与语音合成模型。
- 支付体系、会员自动续费与完整内容风控审核后台尚未全部上线；生产环境需通过环境变量开启图片安全审核（`MODERATION_ENABLED=true`）。
- 早期 `services/generator.js` 本地占位生成与 `dev` 微信云开发回退路径暂作保留，后续确认不再需要后可逐步下线。

## 9. 开发验收顺序

每次开发按以下顺序验收：

1. 数据是否绑定正确的猫咪身份。
2. 主流程是否少于预期步骤。
3. 空状态、加载态、失败态是否可操作。
4. 私密素材是否默认私密。
5. 是否遵循言喵视觉 Token 和小程序性能约束。
6. 是否增加了对应的文档、优先级和验收指标。
