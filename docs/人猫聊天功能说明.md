# 人猫聊天功能说明

## 优先级

- 优先级：P1，基础陪伴能力。
- 依赖：P0 猫咪档案；聊天窗口不允许在没有猫咪档案时进入可发送状态。
- 当前版本：聊天页已经改为服务端真实模型链路；聊天记录按账号与猫咪分别保存在服务端，客户端仅做缓存以提升打开速度。除非用户主动清空，否则服务端不会自动删除聊天正文。

## 产品规则

1. 必须先创建至少一只猫咪，才可以使用聊天。
2. 聊天窗口可以切换当前猫咪；切换后读取该猫咪独立的聊天记录。
3. 回复角色上下文来自猫咪档案中的名称、年龄、外貌线索、性格、喜欢和不喜欢。
4. 私密资料和聊天记录默认只对当前用户可见，不默认分享；聊天记录会同步到云端，用户可在当前猫咪会话中主动清空。
5. 聊天模型列表使用灵泉 AI 聊天页当前可见榜单前 6：Kimi K3、混元 4、千问 4 Max、混元 4 Flash、Kimi K3.1 Pro、DS-V4.1-Flash。

## 真实模型链路

- 客户端只提交 `catId`、消息和模型 ID 到 `POST /v1/chats`，服务端从猫咪档案与 `cat_persona` 组装 system prompt，再调用 OpenAI Chat Completions 兼容接口。
- 服务端优先读取 `CHAT_BASE_URL`、`CHAT_API_KEY`、`CHAT_MODEL_IDS`；未单独配置时会复用已有的 `OPENAI_BASE_URL` / `OPENAI_API_KEY`。模型 ID 必须填写上游真实 ID，不能把界面展示名（例如 `hunyuan-4-flash`）直接当作上游 ID；当前默认使用 `kimi-k3,tt-6-luna,qwen4-max,hy4-flash,kimi-k3.1-pro,deepseek-v4.1-flash`。
- 发布小程序前必须同步部署 `server/src/app.js` 和 `server/src/modules/chats/routes.js`；如果远程服务仍返回 `POST /v1/chats` 不存在，说明线上 API 还是旧版本，不能通过前端兜底成模拟回复。
- 每次成功回复消耗 1 次额度，模型失败会退还额度，并在 `credit_ledger` 留痕。

## 验收指标

- 无猫咪档案时，聊天页显示建档引导，输入框不可用。
- 创建 2 只猫咪后，可以在聊天窗口切换猫咪，且两只猫的消息记录不串线。
- 猫咪姓名、性格、喜欢/不喜欢会影响本地预览回复。
- 发送、等待、回复失败重试状态清晰，消息按时间顺序流畅展示。
- 再次打开聊天页时，按当前猫咪从服务端恢复历史消息；清空操作同时删除云端记录和本地缓存。
- 模型选择默认榜 1，可切换前 6 模型并在本地记住选择。
