# 猫咪档案年龄修复（P0）

2026-11-10：修复创建档案时填写年龄 `1` 导致“服务异常，请稍后重试”的问题。原页面把年龄写入 `birthday`，数据库的 date 字段无法保存年龄文本。

## 字段与依赖

- `age`：用户填写的年龄描述，最多 32 字符，可为 `1`、`2 岁`、`1岁6个月`；空字符串表示清空。创建、更新、详情和列表均支持，编辑页面读取同一字段。
- `birthday`：独立生日字段，仅接受有效 `YYYY-MM-DD` 日期，返回同格式字符串；非法日期由参数校验返回 `400 / VALIDATION_FAILED`。不根据年龄推算或伪造生日。
- 依赖自建 API、现有登录会话及数据库迁移 `003_cat_age.sql`。迁移只新增可空字段，不修改已有生日和猫咪资料。
- 上线顺序：先运行 `cd server && npm run migrate`，再更新后端和小程序。

## 验收

1. 名字、年龄 `1`、外貌“布偶”、性格关键词可成功创建。
2. 编辑时年龄正确回显，可改成 `1岁6个月`，也可清空。
3. 非法生日 `1`、`2026-02-30` 返回参数错误；合法闰日 `2024-02-29` 正常保存。
4. 未填年龄的原档案仍可读取；保存和读取均沿用账号权限校验。

回归入口：在隔离开发数据库运行 `node server/scripts/cat-profile-test.mjs`，测试执行实际页面保存逻辑与后端路由；再运行已有账号与创作冒烟测试。
