# 2026-11-09

## 言喵后端：确定托管方案并落地骨架

**决策**
- 托管选腾讯云轻量应用服务器（上海，2核2G，Ubuntu 22.04），用户已有备案域名。
- 明确不用微信云开发：数据要支持「多端共用」（微信小程序 + 抖音小程序 + 后续 H5/App），云开发的数据库无法被外部端直接访问。
- AI 生成沿用 `双端小程序混合云架构建议.html` 的既定方案：火山方舟 Seedream。
- 媒体文件存 COS 私有桶，客户端直传，业务服务器只签名。

**实现（新增 `server/`）**
- Fastify 5 + PostgreSQL 17，纯 HTTP API，统一响应 `{ ok, data }`。
- 账号模型：`app_user` + `user_identity` 分离，**手机号是唯一跨端合并键**（抖音拿不到微信 unionid，只能靠手机号）。
- 任务队列用 PostgreSQL `FOR UPDATE SKIP LOCKED`，不引入 Redis（2G 机器省内存）。
- 存储驱动抽象：配了 COS 走 COS，没配走本地 `.storage/` + `/dev-storage/*`。
- 生成链路：提交任务 → jobId → 轮询；失败退避重试、僵尸任务回收、额度扣减与退还。
- 客户端 SDK：`miniprogram/utils/adapter.js`（wx/tt 差异收敛）、`utils/request.js`（token + 401 刷新）、`services/api.js`。

**验证**
- `server/scripts/smoke.mjs`：登录→建档→上传→生成→保存 全链路通过。
- `server/scripts/identity-test.mjs`：H5 与微信同手机号合并到同一 user、抖音账号隔离、跨用户越权返回 404，全部通过。
- 本地建立了 `yanmiao_dev` 数据库，已跑 migration + seed（17 个模板）。

**文档**
