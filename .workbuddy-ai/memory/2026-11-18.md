# 2026-11-18

## 静态资源迁移 COS + CDN（static.missmeow.net）打通

**根因（403 的真正原因）**
- CDN 域名、HTTPS、源站绑定本身都正常，问题不在 CDN 配置。
- 403 来自 COS 对象 ACL：`static/` 前缀下 109 个对象的 ACL 是 `default`（桶私有读），CDN 匿名回源拿不到对象。
- 子账号 `yanmiao-server` 无 `PutBucketPolicy` / `GetBucketPolicy` 权限，因此「桶策略按前缀开放匿名读」这条路走不通；但 `PutObjectAcl` / `DeleteObject` 有权限。

**落地做法**
- 用子账号批量 `putObjectAcl: public-read` 处理 `static/` 前缀 109 个对象；同时删除 6 个 macOS 产生的 `._*` AppleDouble 垃圾对象。
- 桶本身仍是私有读写，匿名列举被拒；`u/` 用户媒体仍私有（`https://static.missmeow.net/u/` 返回 403，已验证）。
- `server/scripts/sync-static-assets.mjs` 上传时显式带 `ACL=public-read`（可用 `STATIC_ASSETS_ACL` 覆盖），保证后续 `npm run sync:assets` 不会又把对象改回私有。

**代码改动**
- `src/config.js` 新增 `cos.cdnPublicMedia`（env `COS_CDN_PUBLIC_MEDIA`，默认 false）。
- `src/services/assets.js`：公开作品只有在 `cdnPublicMedia=true` 时才用 CDN 域名，否则继续签名 URL —— 否则 6 条 `visibility=public` 的私有作品会变成 CDN 403。
- `src/modules/assets/routes.js`：302 跳转前先 `stat` 本地文件，不存在的键直接 404（原先会 302 到 CDN 再拿 403，排查成本高）。
- `.env.example`、`docs/后端架构与部署手册.md`、`docs/服务端.env填写指南.md` 同步说明。

**生产部署**
- 生产 `.env` 原先是 `COS_CDN_DOMAIN=` 空，已改为 `https://static.missmeow.net`，并加 `STATIC_ASSETS_FROM_COS=true`、`COS_CDN_PUBLIC_MEDIA=false`；备份在服务器 `/root/yanmiao-env-backup-*.env`。
- `deploy/deploy-server.sh` 跑通：sync:assets 109 文件 / 52,565,236 字节 → pm2 重启 → healthz、legal 页面校验通过。
- 生产验证：`/assets/brand-logo.png` → 302 `https://static.missmeow.net/static/brand-logo.png` → 200 (317,825 B)；全量 109 个对象经 CDN 校验字节数一致（108 一次通过，1 个偶发 connection reset，重试 3 次均 200）。

**遗留 / 下一步**
- 小程序后台需把 `https://static.missmeow.net` 加入 **downloadFile 合法域名**（3D 猫 GLB 走 `adapter.downloadFile`，302 跳转后的域名也要在白名单里，否则真机加载失败；`urlCheck:false` 只在开发者工具生效）。图片 src 不受此限制。
- 公开作品如果要也走 CDN，需在 CDN 控制台为 `static.missmeow.net` 开启「私有桶回源」服务授权，然后才能把 `COS_CDN_PUBLIC_MEDIA` 置 true。
- 子账号 CAM 若想用 API 管 CDN，需补 `cdn:DescribeDomainsConfig` / `cdn:UpdateDomainConfig`，resource 为 `qcs::cdn::uin/100049496595:domain/static.missmeow.net`。
- 本地沙箱访问 CDN 大文件会出现 `transfer closed`（代理限制），验证请在服务器上跑 curl，不要以本地结果为准。
