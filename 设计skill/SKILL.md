# 言喵 · MEOW POP Design System

> **品牌**：言喵 / Miss Meow  
> **官方 Slogan**：和猫一起，把日子过得可爱一点。  
> **核心原则**：可爱但不幼稚，活泼但不吵闹，精致但不繁琐。  
> **视觉基准**：`assets/approved-home-reference.png`；眨眼动态参考：`assets/approved-home-motion.gif`。

## 0. 使用顺序（强制）

1. 在设计/编码之前先查看 `assets/approved-home-reference.png`，并读取 `references/design-tokens.json`。
2. 明确页面属于 **品牌主视觉型 / 内容工具型 / 沉浸媒体型 / 数字空间型** 哪一类。
3. 保持全局品牌、色系、字体级别、组件质感、吉祥物一致；按页面任务调整信息密度。
4. 优先使用已有组件与 Token；不得自行引入不相干的设计流派。
5. 按本文第 12 节的检查单做视觉与交互验收。

## 1. 品牌不可变项

- 品牌中文名称：**言喵**（不使用「喵女子生活」等旧名称）。
- 英文识别：**MISS MEOW**；中文界面优先展示「言喵」。
- 品牌口号：**和猫一起，把日子过得可爱一点。** 不得擅自改写。
- 吉祥物：**圆头黑猫、硕大金黄色圆眼、粉色内耳、短小鼻子、灵动尾巴**。常从**浅粉色纸盒**探出头，两只前爪搭在盒沿。保持 IP 五官比例与角色辨识度。
- 品牌语言：**MEOW POP / 轻潮流手账拼贴**，带细腻半立体纸贴质感、鲜明排版，拒绝纯儿童卡通、过度甜美、重玻璃拟态和厚重拟物。
- 核心情感：独居/独处生活里的轻松与陪伴，不营销焦虑，不强制签到。

## 2. 已确认首页的固定元素（需要忠实保留）

顶部页面导航：左侧黑猫小图标 +「言喵」品牌字样及粉色手绘下划线；右侧搜索和信封/消息入口。

主视觉卡片：
- **柔和天空蓝云朵背景**，右上或右侧的**奶油黄色大圆形**，白色云形边缘。
- 顶部左侧双圆形头像贴纸（女主人头像、猫咪头像），周边粉色小爱心。
- 右侧黑猫从浅粉色纸盒探头，纸盒带浅蓝猫咪图标、猫爪吊牌。
- 小贴纸：奶茶、蛋糕/书册、花束、粉色格纹胶带、黄色感叹号、黄色手绘划线等，**只在主视觉区域适量出现**。
- 大写蓝色 + 深海军蓝 **MISS MEOW** 大标题；蓝色与深色叠加构建强对比，下面有奶油黄笔刷下划线。
- 中文口号须完整呈现：**和猫一起，把日子过得可爱一点。**
- 大圆角（约 26–32px），薄白描边/浅柔阴影，主卡片是首页视觉锚点。
- 若用户要求「保留顶部主卡片」，禁止替换画面主体、重新排列核心贴纸或改变原有视觉重心；只做用户明确指定的文字/细节调整。

主卡片以下沿用更克制的 UI：
- 轻量 3 个快捷 CTA：**生成漫画 / 今日穿搭 / 和主子聊聊**；横向简明、较小圆角胶囊卡。
- **今日喵事**：两个横排缩略图轻卡，如「喵日记」「猫猫时装秀」。
- **云上小家**：单条横向入口，不使用复杂宫格堆满首页。
- 首页主要信息区留白充足；避免把 AI 短视频、挂件、市集等所有功能都在首屏展示。

## 3. 设计 Token

权威机读数值在 `references/design-tokens.json`。它们是依据参考图建立的**工程近似值**，不是逐像素精确取色/字体识别结果。

配色策略：**60–70% 暖白/极浅蓝底色 + 20–30% 天空蓝与深海军蓝主体 + 10% 以下粉/黄点缀**。粉色绝不铺满全屏。

建议：
- Page background `#F8F7FB`
- Sky blue `#B8D7FF` / deeper blue `#78B4FB`
- Cream yellow `#FFE27A`
- Accent pink `#F5A9C9`
- Rose action highlight `#F66E9C`
- Ink navy `#20243C`
- Brand cobalt `#2557D6`
- White card `#FFFFFF`
- Soft gray text `#85899B`

## 4. 字体与排版

- 中文：优先系统中文无衬线字体，字重 Medium/Semibold/Bold，确保微信小程序兼容；不要依赖分发未经许可的字体文件。
- 英文主视觉：厚重、略有手绘弹性、紧凑叠排的大写展示字体，**作为品牌海报元素使用**；普通按钮不使用手绘大字。
- 字体级别：品牌 21–24px / 首屏海报英文 30–42px / 区块标题 16–18px / 卡片标题 13–15px / 正文 12–14px / 说明 10–12px。
- 对齐：功能区以左对齐为主；卡片内文本短、可扫读。禁止一屏有 5 种不同字风。
- 主标题先确定安全可读的文字和行距，再安排贴纸，不让装饰挤压正文。

## 5. 卡片、组件、质感

- 首页 Hero 圆角约 28px，普通功能卡 16–20px，按钮 14–18px，胶囊按钮 999px。
- 卡片用白底或极浅彩色底，细白描边或轻阴影；阴影应扩散、低对比，避免厚重黑阴影。
- 图标：圆润线性/少量双色扁平图标，线宽一致，不用混搭 3D、拟物和彩色 Emoji 图标占位作为正式交付。
- 功能入口保持统一：小插画/图标 + 简短名称 + 必要的一行说明；减少层层套卡。
- 背景不做全屏复杂贴纸重复纹理；装饰集中于品牌大卡和必要的专题头图。
- 页面使用 8pt 间距系统（4/8/12/16/24/32）。首页左右内容边距建议 20px，具体按设备适配。

## 6. 关键页面的风格适配

| 页面类型 | 视觉做法 | 禁止 |
| --- | --- | --- |
| 首页 | Hero 最大、下面内容克制；一屏只突出一个主任务 | 满屏粉色、过密宫格 |
| AI 漫画/故事 | 作品大图 + 三步以内生成；可用蓝黄贴纸小标题 | 大量参数表单 |
| 猫咪时装秀 | 猫咪形象是主角，杂志编辑排版；粉色可适度增加 | 每件装饰都大而抢眼 |
| AI 宠物短视频 | 深色/中性沉浸播放器，品牌色只点缀「同款创作」CTA | 在视频上堆满卡通贴纸 |
| 云上家 | 空间占比优先，浅色浮层操作栏；保持小黑猫入口 | 把家装界面做成多重卡片 |
| 语音互动 | 大猫咪形象 + 语音反馈 + 极简话筒 | 复杂聊天表单 |
| 文创商店 | 商品图干净，分类/价格规范清晰 | 主视图被花朵和爱心盖住 |
| 个人中心 | 清晰头像、猫咪档案、作品与隐私设置 | 杂乱的信息面板 |

## 7. 吉祥物动态语言

轻动态：眨眼（两眼合上再张开，1 次/5–9 秒不规则）；尾巴小幅左右摆（约 2–4 秒）；偶尔探头/轻轻趴低；单颗心贴纸缓慢浮起。动作错峰进行，避免同时不断摇晃。

- 单次动作约 300–800ms，动画尽量使用 `transform`、`opacity`。
- 用户不操作时保持克制，默认提供减弱动态选项；支持系统的减少动态偏好（如技术环境允许）。
- 加载动效复用黑猫角色，不换成无关卡通。
- 动画不能遮挡主 CTA，也不能循环制造性能压力；低端设备减少同时动画数。

## 8. 低负担交互原则

- 默认使用猫咪档案和上次偏好；**拍照 → 生成 → 分享**，通常最多三步。
- 明确的主 CTA 一屏最多 1–2 个；快捷入口最多 3 个。
- 不要求每日打卡、不制造「连续签到中断」惩罚。
- AI 生成有等待时，给出黑猫轻互动和清晰进度/状态，而不是空白加载。
- 真实照片/家居视频/声音属于私密素材，分享、公开和共同创作默认采用清晰授权。

## 9. 微信小程序实现约束

- 微信导航栏、安全区、屏幕宽度、文本缩放、低端机性能必须考虑。
- 支持响应式尺寸，避免把设计稿按固定像素整体放大。
- 交互命中区域推荐至少 44x44 CSS px 或平台等效范围。
- 制作多版本图需分别导出静态插画和动效资源，避免将整页 GIF 直接当交互首页。
- 大面积插画适当 WebP/AVIF（以小程序实际支持为准）；动效可用 CSS、序列帧或轻量动画方案。
- 图片文本与前端真实文案分离，品牌展示文字尽量真实渲染，减少生成图片文字错误。

## 10. 组件/页面命名建议

- `BrandHeader`：黑猫图标、言喵、消息入口。
- `HeroDiaryCard`：品牌主视觉、猫咪探头、品牌标题与口号。
- `QuickCreationActions`：生成漫画、今日穿搭、和主子聊聊。
- `TodayMeowSection`：今日喵事，两张入口卡。
- `CloudHomeEntry`：云上小家横向卡。
- `MascotMotion`：眨眼/尾巴/轻探头。
- `MeowPillButton` / `MeowContentCard` / `SectionHeading`：共用组件。

## 11. 给 AI 设计/编码工具的工作提示

> 你正在设计「言喵 Miss Meow」微信小程序。请先阅读此 SKILL 和 `references/design-tokens.json`，观看 `assets/approved-home-reference.png`。沿用已确认的 MEOW POP 视觉：暖白留白、天空蓝云朵、奶油黄圆形、粉色小点缀、深海军蓝文字、粗体英文编辑排版、轻立体手账贴纸、黑猫黄眼粉耳吉祥物。遵守品牌名「言喵」、英文「MISS MEOW」、品牌口号「和猫一起，把日子过得可爱一点。」。新页面优先复用组件和 Token；功能页简洁且可用，不让装饰争抢交互；主视觉风格一致但不要在每个页面无差别复制首页 Hero。输出前逐项核查设计一致性、可读性、易用性和动效性能。

## 12. 验收清单（每页必须检查）

- [ ] 「言喵」字样与口号一致，没有旧品牌名。
- [ ] 吉祥物黑毛、黄色大眼、粉耳、粉盒等 IP 关键特征稳定。
- [ ] 色系以暖白/浅蓝为主体，粉色只是点缀。
- [ ] Hero 的视觉保真度符合参考图；若要求保留则不改核心构图。
- [ ] 标题/说明/交互区层级明确，主按钮一眼可见。
- [ ] 没有无意义的贴纸、四层嵌套卡片和拥挤宫格。
- [ ] 图片比例、圆角、图标样式、间距与 Token 一致。
- [ ] 快速操作路径不超过预期步骤，等待、失败、空状态清晰。
- [ ] 动效幅度轻且不遮挡；可降低动态和动画负载。
- [ ] 真机/模拟器覆盖小屏、长文字、底部安全区。
- [ ] 审核私人照片、声音、家居视频的默认隐私设置。

## 13. 变更规则

这套系统是**已确认视觉基线**，不是永不可改。用户明确要求调整时可版本升级（V1.1、V2.0）；没有明确要求时，不为了追求潮流而随意变更主品牌色、黑猫造型或 Hero 结构。改动需说明是否影响品牌资产、通用组件与既有页面。
